The option a list's cursor is on, and the picked day, time and month of a calendar, are visible in Windows High Contrast (forced colors): the active option of a `Select` and an `Autocomplete`, the active item of a `Menu`, the picked day and today in a `DatePicker` and a `DateTimePicker`, the picked time slot, and the current month or year in the month picker (#141, part of #135).

In forced colors the browser swaps every authored colour for a system one, so the fill that marked a list's cursor (`--bg-subtle`), the picked day (the primary fill) and the picked time became the same white as everything around them. The cursor of a list is not the DOM focus, so there was no focus ring to fall back on either: a keyboard user could not tell which option an arrow key was on. Measured with the browser's emulation on the docs pages, before: 7 of the 37 pages (9 of the 111 forced-colors tests) had a marked element that looked like its neighbours, inside what a trigger opens or in the inline calendars; now none does. `styles.css` has the new rules in its `@media (forced-colors: active)` block: an outline in the selection colour on the active option or menu item, a heavy border on the picked day, time and month, and a thin one on today. Borders and not fills, because a fill behind text makes the browser draw a box behind the letters. A selected option keeps its check mark. Nothing applies outside forced colors, and the pictures of the normal mode are identical to before.

What changes for an app:

- **`@sereno-ds/ui/styles.css` is now required for the calendar's day grid and time slots** (the picker already needed it for the focus ring): the border of a day is `border: none` in `.sereno-dtp-days button`, and the border of a time slot is `.sereno-dtp-time { border: ... var(--sd-border) }` with only the colour set inline. Without the import a day and a slot show the browser's default button border.
- A time slot now says whether it is picked with `aria-pressed` (it was only a colour before, so a screen reader did not announce it). A list option and a menu item that the cursor is on carry `data-active`.
- The docs' `forced` Playwright project has a third test per page that opens every popup, moves the cursor with the arrow key and fails when an active, selected or current element looks like its unmarked siblings. Its second test now compares an element with its siblings first, and treats a fill the same colour as the page as no fill.
- Not here: the tone dots of a calendar day (`dayDots`) and the swatches of `CalendarLegend` are plain fills, which forced colors turns into the page colour, so they are not drawn in that mode (they keep their screen-reader text). It needs its own rule: on the picked day the dot is white on a primary fill that forced colors also removes.
